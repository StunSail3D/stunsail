# Database migrations

Alembic is the migration authority for Core persistence. SQLite is the initial
backend; migration code must remain compatible with the planned PostgreSQL
backend.

- Create revisions with `uv run alembic revision --autogenerate -m "short description"`.
- Review generated SQL and constraints; do not assume autogenerated output is
  correct or edit a migration that has shipped.
- Test upgrades and downgrades against a disposable SQLite database before
  merging. Use `STUNSAIL_DATABASE_URL` to select the database.
- Prefer portable SQLAlchemy operations and constraints. Use Alembic batch
  operations for SQLite table alterations.
- Back up production data before upgrades. A failed production upgrade is
  recovered from the pre-upgrade backup; do not promise an in-place downgrade
  for destructive migrations.

The initial revision is intentionally empty: the final schema is deferred until
the Core domain is defined in a later phase.
